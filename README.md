# AI와 도시계획 시민 참여 설문

발표 전·후 설문을 서로 다른 URL/QR로 받고, 익명 참여 코드로 연결해 응답을 Google Sheets에 저장합니다. 결과 화면은 전·후 투표를 비교하고 자유응답 키워드를 자동 시각화합니다. 발표자료는 기존 PPT를 별도로 사용합니다.

## 구성

- `?stage=pre` — 발표 전 설문
- `?stage=post` — 발표 후 설문
- `?view=host` — 발표 전·후 QR 코드와 링크
- `?view=results` — 실시간 결과 대시보드
- `Code.gs` — Google Sheets 저장용 Apps Script 백엔드

## 1. Google Sheets 저장소 준비

1. 새 Google 스프레드시트를 만듭니다.
2. **확장 프로그램 → Apps Script**를 엽니다.
3. `Code.gs` 내용을 기본 코드에 붙여넣고 저장합니다.
4. 함수 목록에서 `setup`을 선택해 한 번 실행하고 권한을 승인합니다. `responses` 시트와 익명 참여 코드가 준비됩니다.
5. **배포 → 새 배포 → 웹 앱**을 선택합니다.
6. 실행 사용자는 본인, 액세스 권한은 **모든 사용자**로 설정해 배포합니다.
7. 생성된 `/exec` 주소를 복사합니다.

## 2. GitHub Pages 연결

1. 이 폴더의 `index.html`을 GitHub 저장소에 올립니다. 저장소 루트에 넣거나 Pages가 지정하는 폴더에 넣으면 됩니다.
2. `index.html`에서 `API_URL` 값을 방금 배포한 Apps Script `/exec` 주소로 바꿉니다.
3. GitHub 저장소의 **Settings → Pages**에서 배포 브랜치와 폴더를 선택해 Pages를 켭니다.
4. 사이트 주소에 다음 경로를 붙여 각각 사용합니다.

```text
발표 전:  https://<사용자명>.github.io/<저장소명>/?stage=pre
발표 후:  https://<사용자명>.github.io/<저장소명>/?stage=post
호스트:   https://<사용자명>.github.io/<저장소명>/?view=host
결과:     https://<사용자명>.github.io/<저장소명>/?view=results
```

`?view=host`에 발표 전·후 QR이 각각 표시됩니다. 각 링크를 QR로 PPT의 발표 시작·마무리 화면에 배치하면 됩니다.

## 진행 방식

1. 발표 시작 화면의 사전 설문 QR을 안내합니다.
2. 참가자는 `가능하다 / 일부 가능하다 / 어렵다` 중 하나를 선택하고 이유를 짧게 입력합니다.
3. 발표는 별도 PPT로 진행합니다.
4. 발표 마무리 화면에 사후 설문 QR을 안내합니다. 참가자는 같은 익명 참여 코드를 사용해 다시 투표하고 감상을 입력합니다.
5. `?view=results`에서 두 설문을 같은 코드 기준으로 자동 연결해 전·후 투표를 비교하고, 키워드 구름을 보여줍니다. 화면은 5초마다 갱신됩니다.

## 응답 연결

사전 설문에서 생성된 참여 코드는 같은 기기·브라우저에 저장되어 사후 설문에 자동 입력됩니다. 참가자가 기기나 브라우저를 바꾸는 경우에는 사전 설문 완료 화면의 코드를 사후 설문에 입력해야 두 응답이 연결됩니다. 코드는 이름, 이메일, 연락처를 수집하지 않는 익명 식별용입니다.

## 참고

- GitHub Pages는 화면 파일을 호스팅하고, 실제 응답 저장은 Google Apps Script와 Sheets가 담당합니다.
- 키워드 구름은 응답에서 띄어쓰기 단위로 단어를 추출하고 기본 조사·기능어를 거르는 간단한 방식입니다. 형태소 분석을 사용하지 않으므로 유사 표현이 나뉘어 보일 수 있습니다.
- 실제 응답 수집 전에 사전·사후 링크로 각각 테스트 제출하고 `responses` 시트와 결과 화면에 값이 들어오는지 확인하세요.
